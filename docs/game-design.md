# 蒸汽竞技场 · 游戏节奏与目标 v0.3

> 2026-09-25 · v0.4：接入新模块机制、实体辅助模块和参考车合法性检查。视觉效果继续后置，未完成模块先用文字占位。

## 0. 一句话

**每一场比赛都是一道构筑题：敌人和地形出题，车间里的零件是答题工具，赢了拿到新工具。**

玩家的爽点是「看着自己的车一点点变强」：

- 格子变多：改装台从 4×3 扩到 8×6。
- 零件变多：每章解锁新模块。
- 材料变好：黄铜 → 熟铁 → 钢 → 镀镍 → 乌兹钢 → 以太合金，颜色一眼就能看出来。

### 0.1 功能优先与视觉占位

新模块先完成尺寸、属性、战斗接口、解锁和缴获流程。没有专用 `DRAW` 造型的模块暂时借用最接近的已有精灵，并在模块卡片和数据表中保留中文名称；如果借形会造成误解，界面使用「占位 · 模块名」文字标签。专用像素画、特效和换皮不作为数值验收条件，后续美术迭代不得改变已验证的尺寸和核心属性。

所有模块仍以 24px 子格为唯一底层单位：1×1、1×2、2×1 和更大的 Boss 件先按占格参与摆放、遮挡、重量和碰撞，再补视觉细节。

- **第 N 章的奖励，就是第 N+1 章的答案。** 第二章拿到撞击件和双足，正好用来撞开第三章那些躲在墙后的车。

- **功能按需出现。** 开局只有「出战」；车间、商店、侧挂层、蓝图库、银行、下注都跟着章节解锁。没解锁的功能完全不显示，不做灰掉的占位。

- 已砍掉「军方收购原型机」：它会卖掉玩家的车，和「车越来越强」的主线冲突。

## 2. 材料 = 品质

| 级 | 材料 | 倍率 | 获取 | 换色 |
|---|---|---|---|---|
| 1 | 黄铜 | ×1.00 | 商店 | 原画 |
| 2 | 熟铁 | ×1.20 | 第一章后花钱升级（原价 ×0.6） | 压暗的枪铁色 |
| 3 | 钢 | ×1.45 | 第二章后（原价 ×1.0） | 蓝 |
| 4 | 镀镍 | ×1.75 | 第三章后（原价 ×1.6） | 银白 |
| 5 | 史诗 · 乌兹钢 | ×2.10 | 原价 ×2.2 + 乌兹钢锭 | 紫 |
| 6 | 传奇 · 以太合金 | ×2.50 | 原价 ×3.0 + 以太结晶 | 青 |

- **放大哪些属性**：耐久、伤害、动力、水、冷却、撞击、活塞、承重、护甲一起放大。**产热和重量不变**，所以好材料同时也更「省」。
- **怎么升级**：在车间选中车上的模块，就能升到下一级。拆下来时材料跟着模块走；库存按「模块 + 材料」分开记。
- **史诗和传奇只能靠收集**：
  - 乌兹钢锭：铁甲圣堂掉落、委托（北方矿业、马戏团）、战役通关奖励。
  - 以太结晶：女王号掉落，终局每个赛季夺冠奖励 1 块。
- **缴获**：只在战役和终局锦标赛里，赢了才能从对手剩下完好的模块里挑一件，街头赛和友谊赛不缴获。候选只有两种：
  - 你还没有的零件：车上和库存里都没有这种模块，或者只有更差的材料。
  - 史诗 / 传奇特殊件：没被打坏就一定在候选里。

  没有符合条件的，就不弹缴获。
- **价值**：修理、卖出、报废回收都按「原价 + 材料升级 + 改装」的总价值计算（`SA.cellValue`）。
- **实现**：`SA.mod(cell)` 返回按材料放大后的模块定义，属性计算和战斗都走它；换色在 `sprites.js` 的 `tintMat`，用 `color` 混合保留原图明暗，按材料缓存。

本轮数值验收增加两条约束：材料升级不能压过新机制模块的购买价值；普通构筑的主要失败原因中「锅炉烧干」应低于 30%。因此冷凝器、散热片和压力模块分别提供水、冷却和动力取舍，产热和重量不随材料倍率降低，避免单纯把材料升满就能跳过热量系统。经济模拟以「每 2～3 场可以买到一件当前解锁的新东西」为合格线，若连续两章只能靠刷街头赛才能升级，先调奖金和升级费，再调 Boss 数值。

## 3. 敌人就是考题

每个敌人 = **一个明确的问题 + 一个看得见的弱点 + 一件可缴获的零件**，赛前点对手就能侦察到。

- **护甲机制**（为考题服务，同时修正了机枪全面压过火炮的问题）：
  - 装甲每挨一发先减掉固定伤害，最少保留 25%。
  - 护甲值：铁装甲 3、重装甲 6、铲斗 5、履带 2、四足 1，随材料放大。
  - 机枪一发 5 点，打装甲只冒火星，专打锅炉、水箱、驾驶舱；直射火炮一发 32 点，负责凿穿装甲。
- **AI 性格**：关卡数据里的 `style` 字段。
  - rush 冲锋：几乎一直在冲。
  - kite 放风筝：保持 400–640 的距离。
  - turtle 龟缩：守在出发点附近。
- **Boss 设计**：每个章末 Boss 都有可读的招牌件和一个可缴获的数值答案；`pressure-buffer`、`range-prism`、`hydraulic-bite` 已分别接入储能、满蓄力无散布和活塞逻辑。

| Boss | 设计语言 | 招牌件 / 掉落 | 玩家要回答的问题 |
|---|---|---|---|
| 煤灰寡妇 | 四足稳定炮台 + 铲斗，逼玩家处理正面推进 | `boss_ram` 寡妇液压撞头 | 甲片护舱还是用火炮先拆撞击面 |
| 双足舞者 | 泥地高速冲锋，低命中但撞角重 | 钢制撞角（现有 `spike`） | 车重、刹车和近战反击如何取舍 |
| 黄铜公爵 | 侧炮藏在装甲后，靠测距和冷枪消耗 | `boss_lens` 公爵测距棱镜 | 先拆侧炮，还是用高抛越过墙 |
| 铁甲圣堂 | 厚重履带、多层装甲、顶射 | `boss_core` 圣堂压力核心 + 乌兹钢 | 过热与重量同时超标时保哪一项 |
| 维多利亚女王号 | 六层移动堡垒，巨炮占据大块空间 | `cannon_giant` 巨炮 + 以太结晶 | 用终局大件换掉多少通用模块 |

Boss 分阶段仍保留为后续工作（女王号掉了上层以后变快），宿敌则跟着玩家的材料进度换构型；当前版本先保证招牌件能被侦察、模拟和缴获。

### 3.1 新模块机制

- **鱼叉**：伤害 10，命中后按 80 px/s 收绳，最多 4 秒；距离超过 760px、目标模块或鱼叉被毁时断开，牵引期间不能再次发射。
- **火箭架**：每 6 秒四发齐射，每发伤害 14，轮内间隔 0.12 秒；命中点 24px 内按距离衰减溅射，装填中的模块被毁会殉爆 22 点。
- **喷火器 / 蒸汽喷射器**：射程 170px、锥角 ±10°，持续造成模块伤害和整车升温；蒸汽喷射器额外每秒耗水 0.5 并小幅击退。
- **蓄压罐 / 散热片 / 冷凝器**：蓄压容量 20、缺动力时每秒最多补 3；散热片提供不耗水散热 1.2/s；冷凝器把冷却耗水倍率降到 0.7，多件最低 0.4 倍。
- **实体辅助模块**：观察镜、装弹机、陀螺仪、测距仪都是可被击毁的 1×1 模块，分别影响瞄准、装填、车身晃动和直射散布。
- **补齐模块**：小臼炮使用 `indirect` 通用字段，双联机枪使用独立的高射速数据；所有机制字段同时进入战斗、车间属性和评分。

## 4. 地形（第一批已实现）

目标：**给移动一个理由，让构筑有针对性。** 赛前公布地形，蓝图库一键换装，这样蓝图库就从收藏夹变成核心玩法。

已实现（`SA.TERRAINS`，战役每关一个 `terrain`）：

| 地形 | 做法 | 它考的是什么 |
|---|---|---|
| 平地 | 没有遮挡 | 火力和装甲 |
| 货箱 | 木箱，耐久很低：能挡一两发炮弹；车一顶上去就碾碎（越重越快，全速一撞就碎），碾的时候车速被拖慢，碎木堆再减速一点 | 主要是减速，外加一点临时掩体 |
| 泥地 | 区间内按底盘减速（履带 0.8、四足 0.65、双足 0.45） | 冲撞车跑不起来，履带占便宜 |
| 土坡 | 地面高度表；炮弹打到地面就停，上坡慢下坡快；整车按坡度旋转贴地，炮口、弹道、射界、命中判定跟着换算 | 低平直射被坡挡住，要靠近或高抛 |
| 工厂后院 / 矿坑 | 组合 | 综合 |

技术上：两车高度不同时，碰撞按世界高度对齐行；弹道预览会提示「被货箱挡住 / 打在土坡上」。美术画法见 `docs/art-direction.md` §12，样机在 `tools/terrain-lab.html`。开发者面板里可以挑场地和对手试驾，数值工具可以把所有关卡换成同一种场地对比。

后续想法：

| 元素 | 它考的是什么 |
|---|---|
| 可破坏的掩体墙 | 直射被挡住 → 用高抛、撞墙，或者绕过去 |
| 高台 / 斜坡 | 火炮 −8° 的仰角限制开始起作用；下坡冲撞有加成 |
| 场地边缘 / 坑 | 击出场外直接获胜，铲斗击退和重车有了真正的价值 |
| 泥地 / 冰面 / 铁轨 | 三种底盘各有擅长的地面 |
| 场地中间的水泵 / 煤堆 | 逼玩家离开出生点，把热量系统和地形挂钩 |

建议先做最小集：**掩体墙（工厂区）+ 场地边缘（码头）**。实现方式是高度图 y(x) 加墙体对象，弹道碰撞多一层地形判定。

### 4.1 悬挂与爬坡（已接进战斗；样机 `tools/suspension-lab.html`）

问题：车身是一块刚体，只按车头车尾两处地面定倾角，跨过凹凸时总有一段底盘悬空。

做法：上层车体保持刚体；底盘每格有两个接地点（履带的两组负重轮、腿式的两只脚），各自在行程内上下伸缩。

- 行程（上收 / 下伸，px）：履带 4 / 8，四足 6 / 12，双足 8 / 3（Mk.II 的腿静止时已经接近伸直）；车身跟坡比例：履带 1、四足 0.85、双足 0.85。参数在底盘模块的 `susp` 字段；蜘蛛四足的脚往外张，接地点由 `SA.suspPts` 算。
- 车身倾角取所有接地点地面高度的最小二乘拟合，车底放在各点的平均高度，但不让任何一点超出行程。
- 绘制函数已支持每格两个接地点的偏移（`renderVehicle` 的 `gnd`），默认 0，游戏里暂时没接上。

沿整条地形每 4px 摆一次姿态的统计（悬空 > 2px 的位置占比 / 最大悬空）：

| | 土坡 | 矿坑 | 台阶 | 搓衣板 |
|---|---|---|---|---|
| A 现在的刚体 | 53% / 12–14px | 58% / 13–14px | 40% / 18px | 89% / 11px |
| B 悬挂，车身全跟坡 | 0% / ≤1.3px | 0% / ≤1.7px | 履带 10% / 4.7px，腿 0% | 0% |
| C 悬挂，车身只跟一半坡 | 腿 0%，履带 36% | 四足 14%，履带 42% | 腿 0%，履带 29% | 0% |

结论与接入计划：

- **车身跟坡的比例**：履带用 B（行程短，车身得全跟坡）；腿式用 C（车身稳、腿吃掉起伏，更「丝滑」），四足可以取 0.7–0.8。
- **性能**：最坏情况下每帧所有偏移都变、缓存全部失效，一台车渲染 1.8ms，可以接受。偏移按整像素缓存，过坡时变化慢，实际命中率更高。
- **已接进战斗**（2026-09-25）：参数在底盘模块的 `susp` 字段；四足跟坡比例取 0.75。长车骑在宽土包顶上时两端仍会悬空（刚体车身 + 8px 下伸行程的几何限制）。原计划：
  - `settle()` 换成上面的姿态解算，并算出每格的偏移。
  - 画车时把偏移传给 `renderVehicle`。
  - 处理边角情况：混装底盘、掉链的履带、被毁的腿不参与悬挂。
- **履带已打磨**：下段履带改成穿过各组负重轮底部的连续折线（跨格连成一条），伸出的减震柱画成螺旋弹簧；尾部链轮和前端诱导轮仍固定在车身上。

## 5. 数值自测（`tools/sim.html`，已实现）

`SA.Battle.simulate()` 让两边都交给 AI，不渲染、不产生粒子，按固定步长一口气打完，每局约 5 毫秒。玩家那一侧用瞄准 0.8 的 AI 代替。

1. **战役关卡检验**：每章一台「参考玩家车」（`tools/sim.js` 的 `REF`，只用前面各章的解锁造出来）。
   - 用本章参考车打本章每一关。
   - 用上一章参考车打本章 Boss。
   - 输出胜率、平手率、平均用时和主要结局，并按合格线标颜色。
2. **对战矩阵 + 评分校准**：参考车、各章 Boss、全部战役对手、官方蓝图、我存档里的车任选。两两对打，一半局数换边，输出胜率矩阵；再按评分比分桶，看实际胜率是否单调上升。
3. **模块性价比**：按材料列出 DPS/£、耐久/£、耐久/吨、DPS/动力、DPS/吨，和同列中位数比较，标出离群值。
4. **构筑淘汰与经济模拟**（`tools/sim.html` 的「构筑淘汰模拟」）：按当时已经解锁的模块和实际关卡奖金生成候选车，改变材料、武器和能源组合，逐关调用 `SA.Battle.simulate()`；预算只限制相对章节基准车的新增改装费，不把已有整车总价重复扣除。低胜率候选淘汰，保留前三，按我方失败原因统计「烧干、被击毁、武器打光、超时、平手」以及现金轨迹。第二轮改良直接复制第一轮候选车，再补一个针对失败原因的模块，不能静默换回章节基线。它是调参环，不是玩家 AI：先用它定位失衡，再回到战役关卡检验确认。
5. **生效统计与失败归因**：战役检验额外累计每个模块的激活、开火、命中、牵引、储能释放、省水和无水散热；逐关表按「我方 / 对方 / 同时」显示失败次数，平局原因中保留双方同时烧干的分类。

### 5.1 节奏验收算法

- 每组默认跑 50 局；战役表在胜率后显示 95% Wilson 区间。50 局以下只作快速试跑，不能据此判定 Boss 的 60–70% 目标。
- 每一关额外统计平局率、平均时长和热量 / 缺水失败率。总体目标是平局 < 5%、平均时长 30–60 秒、热量 / 缺水失败 < 30%；胜率达标但这些指标失控时仍算偏离。
- 参考车在每一关开始前按 `SA.CAMP_START`、之前关卡的 `unlock` 和之前章节的 `unlock` 计算可用模块；开局车实际预装的甲片也列入基线。若参考车提前使用了尚未解锁的模块，结果仍会运行，但在“主要结局”列明确标出，避免把未来答案误当成本关答案。
- 经济轨迹从开局 £300 开始，逐场累加 `stage.prize`；每个解锁节点最多模拟购买一件当前买得起的新模块，记录“距离上次购买”的场数。超过 3 场没有买到新答案就标红。该轨迹不计修理、贷款、街头赛和缴获，作为主线奖金的保守下限。
- 评分矩阵继续用于发现评分公式偏差；构筑淘汰和经济轨迹用于发现“答案出现太晚、买不起或热量代价过高”。两者都只能定位问题，最终仍以实际关卡构筑回归为准。

## 6. 其他已实现

- **实体辅助模块**：观察镜、装弹机、陀螺仪、测距仪都是普通 1×1 模块，装在车上即可生效，被击毁后失效；旧存档中的驾驶舱槽位会在读取时迁移到库存。
- **投降**：对手满足任一条件持续 1 秒就挂白旗：① 开不了火、也撞不了人；② 开不了火、只剩撞击件，耐久不到一半；③ 残血（不到 20%）而玩家的耐久比例是它的 3 倍以上。Boss 只在 ① 时投降。战斗暂停，玩家选接受（立即获胜、额外声望 +1、零件原样保留，缴获选择更多）或继续打。只有对手会投降。
- **齐射**：手操的武器组要全部装好才一起开火（沙漏等最慢的那门），其他驾驶员管的组各打各的（驾驶员人数见 `docs/module-plan.md`）。
- **冲撞**：场地没有墙以后，被撞飞的车靠「打滑急停」停住（超过自身最高速度时减速度 320），单次击退上限 70。
- **子格**：一个大格 = 2×2 小格（24px）。模块记锚点和尺寸，占格表（`SA.V.occ`）负责摆放、连通、遮挡、碰撞和点选。新增甲片 1×1、小水罐 1×1、水罐 1×2、驾驶舱 1×1、中炮 2×1，都按 24px 原生像素画（不再用大模块精灵缩小）。关卡数据仍按大格写。
- **材料换色的例外**：驾驶舱、锅炉、水箱的颜色本身就是辨识度，不整体换色，只在四角钉材料色的角铁。

## 7. 暂不做

- **相邻加成 / 构型系统**：工作量和复杂度太大。
- **图纸和自定义模块**：会让系统变复杂。
- **美术细化**：材料先用简单的换色，小模块先用缩小的大模块精灵。
- **音乐和音效**：搁置（2026-09-25）。
- **云车库服务器存储**：搁置，现在只做分享码导入 / 导出；以后按发布平台再定（2026-09-25）。
