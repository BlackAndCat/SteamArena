## 0. 现状（2026-10-06 读代码）

| 场合 | 现在有的 | 位置 |
|---|---|---|
| 开火 | 炮口火光、烟、制退器气浪、炮口前扬尘；炮弹类震屏；本车后坐弹簧 | `js/battle.js` `fire()` |
| 命中 | 6 粒黄铜火花 + 伤害数字（4 档，弹出放大、≥25 有迸射线、连射合并成 `5×3`） | `damage()`；`js/battle-view.js` `addDmg` / `drawDmg` |
| 弹开 | 白点 + 掠飞线 + 火花 +「弹开」铭牌 | `ricochetFx` |
| 击毁 | 火球爆炸 + 碎片（甲片有碎片）+ 震屏 7 | `destroy()`、`shatterFx` |
| 声音 | 无 | — |

**弱在哪里**

1. **被打的车没有反应**：不闪、不晃，只有数字和几粒火花。这是“打不痛”的主要原因。
2. 没有顿帧：重炮命中和机枪擦一下在节奏上一样。
3. 震屏是每帧均匀随机加线性衰减，没有方向；小炮、重炮、爆炸的震感差别不大。
4. 打中什么都是同一种黄铜火花，铁甲、重甲、木箱、地面没有区别。
5. 镜头拉远时（最小 0.62 倍）弹着点很小，**准星没有命中确认**，玩家不知道打没打中。
6. 自己挨了重炮，座舱没有反应。
7. 没有声音。

**技术前提**：战斗逻辑用 `SA.Battle.emit` 把视觉事件交给画面层，但开火和命中现在只发了粒子和飘字，没有“谁用什么武器打中了哪个模块、打穿没有”这样的事件。没有这个事件，顿帧、闪白、音效都没法按武器 / 材质 / 伤害区分（§4）。

## 1. 目标和验收

- 不看数字也能分辨：**打中没有、打穿还是弹开、打得重不重、打掉了什么**。
- 每类武器有自己的声音：小炮脆、重炮闷、巨炮震、机枪密、迫击炮有呼啸、喷火和蒸汽是持续声。
- **不改规则**：同一个种子的无画面模拟，改动前后结果完全相同（脚本比对）。
- **不吵**：4 倍速、双机枪加喷火的混战里，同时发声数不超过上限，离线渲染的总线峰值不过 0 dB。
- **可调**：总音量 / 音效 / 界面三个滑块、静音、震屏强度、减弱闪光。

## 2. 打击感（纯画面）

| 编号 | 做法 | 触发和分级 |
|---|---|---|
| H1 受击闪白 | 被打中的模块整块变白剪影约 50ms，再用 80ms 退成暖色。`battle-view.js` 已有画白色剪影的 `highlight()`，直接复用 | 所有命中；机枪只闪 1 帧；同一模块 0.1s 内不重复闪 |
| H2 受击晃车 | 被打的车身弹簧朝远离攻击方的方向踢一下（`SA.Dyn.kick`，和开火后坐用同一个弹簧，只影响画面）；重炮命中时车头微抬 | 冲量按实际伤害；机枪极小 |
| H3 顿帧 | 只在实时循环里暂停战斗推进一小段，画面照常绘制（粒子、数字冻住） | ≥25 伤害 0.04s；≥50 0.07s；击毁模块 0.09s；爆炸或驾驶舱被毁 0.12s；机枪、喷火、蒸汽不顿；0.25s 内不叠加；2 倍速以上减半 |
| H4 震屏重做 | 改成“创伤值”模型（震幅 = 创伤值²，平滑噪声代替每帧随机跳），沿弹道方向先推后回弹；巨炮和爆炸加一帧 +2% 镜头缩放 | 机枪命中 0；小炮 0.15；重炮 0.35；巨炮 0.6；爆炸 0.8；离镜头中心远的减弱 |
| H5 弹着星芒和材质粒子 | 弹着点 2～3 帧像素星芒，大小按伤害档；粒子按材质分：铁甲白黄火花 + 铁屑，重甲火花少而亮 + 一圈冲击环，木箱木屑，地面土块 + 尘柱 | 材质按模块 id 分组，对照表放 `js/module-art.js`（视觉字段） |
| H6 打穿和弹开分开 | 打穿：星芒后面跟一道向内的暗色冲击（弹孔感）；弹开保留现有效果 | 需要事件里带“打穿 / 弹开”（§4） |
| H7 准星命中确认 | 玩家的弹命中时，准星外圈闪一下、四角标记往里收；击毁模块时变红并停 0.3s | 只对玩家的射击 |
| H8 挨打反馈 | 玩家被 ≥25 的命中打中时，座舱仪表盘边缘红光一闪、指针抖一下 | 按 HUD 规则只反馈自己，不显示敌人状态 |
| H9 击毁残件 | 被击毁的模块弹出一块残件精灵：翻滚、落地弹一次、在地上停几秒后淡出；代替只有粒子 | 每场残件数设上限 |
| H10 累积损伤（排后） | 模块耐久低于 2/3、1/3 时出现凹坑 / 弹孔 / 焦痕；只记在画面层，不进存档 | 美术量大，放最后 |

所有分级参数集中成一张表（`battle-view.js` 里的 `FEEL`），试听台上有滑块可以直接调。

## 3. 音效

### 3.1 音源（待定，见 §7 D2）

| 方案 | 好处 | 问题 |
|---|---|---|
| A 程序合成 | 用浏览器自带的 Web Audio 现场合成：没有文件、没有授权问题，符合“无依赖、无构建”；每次播放随机微调音高和长度，不会机械重复；蒸汽嘶声、金属撞击、棘轮、电报滴答这类声音合成效果好 | 大爆炸、巨炮的“厚度”难做，可能偏电子游戏机的声音 |
| B 免费授权素材 | 真实录音，质感好（例如 Kenney 的 CC0 音效包、Freesound 上的 CC0 录音） | 要逐个挑选、剪裁、统一响度和格式，要记录授权；要下载文件（每次下载先问你）；包体约 1～3 MB |
| **C 混合（推荐）** | 先全部用合成做出来；你试听后，不满意的几个主力声音（重炮、巨炮、爆炸）再换成素材 | — |

**我听不到声音。** 我能做的是离线渲染后测响度、峰值、时长和频谱，保证不爆音、各声音音量一致；好不好听、够不够劲，要你在试听台上判断。所以流程围绕试听台来走（§5）。

### 3.3 混音规则

- 总线：音效 / 界面 / 环境三路 → 总音量 → 压缩限幅器。
- 声像和距离：按声源在屏幕上的左右位置分声道；离镜头中心越远越轻。
- 同类限流：每种声音同时最多 N 个（机枪 4、命中 6），超出就顶掉最老的；30ms 内同种、同位置的声音合成一个更响的。
- 优先级：爆炸 > 击毁 > 重炮 > 命中 > 机枪 > 移动；爆炸时其他声音压低 0.3s。
- 持续声（喷火、蒸汽、行驶、挤压）用循环加淡入淡出，**不按每 0.1s 的伤害结算一下一下响**。
- 倍速：2 倍以上，移动循环跟着升调，零碎命中声抽稀。
- 浏览器要求第一次点击或按键后才能出声，iOS 触屏同样处理。
- 音量设置存在单独的 `localStorage` 键（例如 `sa-audio`），**不碰存档格式**。

### 3.4 代码结构

- 新文件 `js/audio.js`（Opus）：`SA.Audio.play(名字, { x, vol, pitch })`、`loop(名字, key)` / `stop(key)`、音量、静音、解锁。合成配方表里每个声音分几层（起音瞬态 + 主体 + 尾音），启动时离线预渲染成音频缓冲，每个配方 3～4 个变体。
- `js/battle-view.js`：一张事件对照表同时管画面和声音——同一个 `hit` 事件驱动闪白、晃车、顿帧、震屏和音效，参数在一处调。
- 界面音：在像素按钮、编辑器拿放等少数入口挂钩。
- `index.html` 加载新脚本。

## 4. 需要战斗逻辑多发的事件

`js/battle.js` 归 astra。需要加的都是**通知**：不改任何状态、不调用战斗随机数 `random()`、无画面模拟时直接返回。

| 事件 | 在哪里发 | 带什么 |
|---|---|---|
| `fire` | `fire()` | 哪一方、武器 id、弹种 `proj`、直射 / 高抛、炮口坐标、齐射数 |
| `hit` | `damage()`（`projectileDamage()` 知道打穿还是弹开） | 被打方、攻击方、层、模块 id、材料等级 `mt`、实际伤害、坐标、伤害来源（炮弹 / 子弹 / 火焰 / 蒸汽 / 近战 / 爆炸波及 / 撞击）、是否打穿 |
| `kill` | `destroy()` | 模块 id、坐标、哪一方、是否引爆 |
| `ground` | 炮弹落地 | 坐标、是否大弹 |
| `melee` | 近战 / 撞击接触开始和结束 | 坐标、种类、力度 |
| `vent`、`overheat`、`chuff` | 泄压、过热、锅炉憋气 | 哪一方 |

跳跃、落地、脚步可以由画面层从车辆状态自己判断（`bipedAir` 已经这样做）。

**验收**：一批固定种子的无画面模拟（`tools/sim.js` 或 html5-game MCP），加事件前后结果逐位相同。谁来加见 §7 D3。

## 5. 开发流程（两页流程）

1. **音效试听**：每个声音一个按钮，连点听不同变体，旁边显示峰值和响度。

## 8. 风险

- **顿帧让操作发卡**：只给重击，有冷却，倍速减半，可以关。
- **机枪和喷火事件太密**：限流、合并、改用循环声。
- **我听不到声音**：好坏靠你试听；我负责测量，保证不爆音、响度一致。
- **性能**：约 35 × 4 个短音频缓冲，内存只有几 MB；新增粒子数有上限。
- **光敏**：闪白限制面积和频率；“减弱闪光”接到已有的场景动效开关（`SA.Scenes.fxOn`）。
