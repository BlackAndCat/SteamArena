## 排序原则

1. 已完成的排在最前。
2. 未完成的先看**出镜多少**（底盘每台车都有），再看**玩家多早见到**（章节越早越靠前），再看**有没有特效要配**（特殊武器单独一档）。
3. 保留原有文字占位的优先级；五个新增尺寸的模块已经接入功能与占位，按第三档的顺序继续画。
4. 唯一件每个存档只见一次，排在普通模块后面。
5. 已经画好、只差按新规范统一的旧模块最不急，排在最后。

## 第 3 档的交代说明（2026-09-28 用户新增）

用户的要求：

1. **锅炉**：要做 1×2 竖版，**锅炉最小就是 1×2**；另有 3×3 大型锅炉。**水箱**也要 3×3 版本（先计划占位）。功能和数值由 astra 做。
2. **机枪系列**：1×1 车载机枪、1×2 重机枪、2×2 机炮（就是现在的 2×2 机枪），**最大到 2×2 为止**。
3. 现在的 2×2 机枪**改名「机炮」**，并**标记为画面材质需要后期修改**。

做的顺序：

1. **astra 先做**（交接见 `docs/board-opus.md`）：五个新模块的数据、功能、数值、解锁位置；2×2 `mg` 的显示名和相关文案改成「机炮」。
2. **astra 落地后，Opus 马上接占位**：在 `js/module-art.js` 给新 id 加 `placeholder`（文字占位，尺寸按 24px 子格），保证游戏里能摆、能看、能分清；同时把本表和 `tools/art-progress.js` 里的暂定 id 换成实际 id、「章节」换成实际解锁位置。
3. **按第 3 档的顺序画**：车载机枪 → 重机枪（先定下机枪系列的语言）→ 竖式锅炉 → 大型锅炉 → 大水箱（最后）。
4. 机炮的重画留在第 7 档：等机枪系列语言定了再回头按同一语言重画。

兼容性（要 astra 一起确认）：

- **id 不改**：现在的 2×2 继续叫 `mg`，只改显示名为「机炮」。分享码按 `SA.MODULE_ORDER` 的序号编码，新模块只能**追加到末尾**，旧存档、旧分享码、蓝图库、关卡车（`js/stage-cars.js`，用户专属）里的 `mg` 都不受影响。
- **文案**：所有指 2×2 `mg` 的「机枪」都要改成「机炮」（模块名、描述、开局库存说明「一挺机枪」、教程、HUD 提示、`text/` 里的覆盖文案）；AI、关卡数据里的 id 不动。
- **画面**：2×2 机炮的精灵先不动（只改名）；它的画面材质已标记后期修改。
- **3×3 尺寸**：确认改装台摆放、占格校验、`SA.fp` 都支持 3×3（重炮 3×2 已经有奇数宽，但 3 高是第一次）；早期改装台只有 5×3 大格时能不能放下由 astra 定。
- **锅炉最小 1×2**：加压舱 `pressure_chamber`（1×1）和圣堂压力核心 `boss_core`（1×1）不算锅炉，不受这条限制——如有冲突请 astra 提出。

用户已定（2026-09-28）：

## 做一个模块的流程

**两页分工（2026-09-28 用户定）**：`tools/module-candidates.html`「模块造型 · 全部进度」看全部；`tools/current.html` + `current.js`「当前开发」只放正在开发、等用户确认的东西，**不复用**——用户确认后把本期页面和脚本复制到 `tools/archive/<名字>.html / .js`（改好相对路径），在 `tools/labs.js` 登记成历史存档，`current` 换成下一项。两页都在游戏开发者面板和样机馆「总览」的最上面。

1. 在全部进度页按类别找到它，请用户挑候选或给方向。
2. 在「当前开发」页里迭代（火炮类参考 `tools/gun-family-lab.html` 的做法：分区图 + 各档对照 + 仰角 / 状态检查）。
3. 用户定稿后搬进 `js/sprites.js`（`DRAW` / `OVER`），外观字段写在 `js/module-art.js`，去掉 `art` / `placeholder`。火炮的出膛口、角度、动画数据（`piv` / `blen` / `barrel` / `rcPx` / `back` / `ret`、仰角范围 `elev`、静止角 `rest`）都由 Opus 按画面定，不用等 astra（`docs/collab.md` §2.3）；astra 只管数值和功能正常。
4. 更新 `js/build-vis.js`，改本表和 `tools/art-progress.js` 的状态，在 `docs/board-opus.md` 记一笔。
