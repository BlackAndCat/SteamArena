## 当前问题

未达标原因计数如下：`target=7`、`rewardLowerBound=7`、`previousBoss=6`、`terrain=2`、`rewardContrast=2`、`reward=1`、`bossGeneric=1`。这些是预演筛选条件未满足的记录，不代表战斗代码抛异常，也没有把候选写回 `js/content.js`。

第 3 章第 2 关最终使用了“保底候选”，说明该关在当前预算、尺寸和奖励约束下的随机搜索收敛质量偏低。第 4 章第 3 关出现奖励条件失败，说明奖励件的实战效果门槛仍比“能合法放进去”严格。上一 Boss 对比失败在第 2～6 章持续出现，应该优先检查代际标尺和奖励车强度约束，而不是先调整战斗数值。

长跑中曾在第 4 章第 2 关因奖励件合法摆放随机失败而整轮退出。原因是奖励件旋转 / 落点成功率低，初始化只重试 24 次；现在已提高到 128 次，并在 8×1 全战役烟测和 24×4 完整预演中验证不再中断。

`tools/out` 当前受本机权限限制，报告入口会自动写入 `tools/evolve-preview.json`，并把实时状态写入 `tools/evolve-progress/`。这属于输出路径问题，不影响模拟结果。

## 性能瓶颈

1. **战斗物理循环是主瓶颈。** CPU 分析显示耗时集中在 `js/battle.js` 的 `sim`、`drive`、`settle`、`step`、`muzzle`，以及投降 / 碰撞处理；AI 决策链较短，不是主要耗时来源。
2. **合法车辆统计有重复计算。** 随机车辆检查中，`vehicle.js` 的 `overheatTime` 约占 35%，`SA.coolRate` 约占 14.5%。适合做结果保持不变的局部缓存，并减少同一候选上的重复 `stats` 调用。
3. **缓存只能解决重复证据对局。** 当前单次预演缓存命中率 52.0%，但早期 2 章小基准只从 31.67 秒降到 31.16 秒，约 1.02 倍；原因是候选评分的大多数 duel 只有一次请求。
4. **worker 并行是当前收益最大的改动。** 相同固定种子下，2 章、4 候选、1 代、1 局的同步 / 异步结果哈希一致，耗时约 24.5 秒降至 9.4 秒，约 2.59 倍；完整长跑因此可以持续输出中间状态并完成。

## GPU 可行性

机器有 RTX 5070 Ti（16,303 MiB，compute capability 12.0），但 Node v24.14.0 没有 `navigator.gpu`，`--experimental-webgpu` 也不支持。当前战斗状态机包含碰撞、遮挡、可变结束时间和大量分支；只把短 AI 决策链搬到 GPU 预计收益有限。若以后试验 GPU，需要把整个战斗步进重写成 WGSL / CUDA 数据布局，并用固定种子逐事件差分验证，不能直接替换当前 worker 路径。

已用浏览器 WebGPU 做了独立批量算术基准（`tools/gpu-benchmark.html`）：RTX 5070 Ti 的 `nvidia / blackwell` adapter 对固定输入的 CPU / WGSL 结果最大误差为 `3.81e-5`，全部一致；重复 5 次时，4K / 16K / 64K / 262K / 1,048K 候选的 GPU 含回读加速分别为约 `0.00× / 0.02× / 0.11× / 0.39× / 0.95×`。这只是可批量预筛算式，当前预演 1,632 次候选远未达到回读平衡点，因此不接入正式生成器。

## 后续建议

优先做不改变规则结果的 `overheatTime` / `coolRate` 局部缓存和 `stats` 重复调用削减，再评估把 worker 任务从“每候选一个消息”合并为小批量。选关失败应先按 `target`、`rewardLowerBound`、`previousBoss` 分组调整搜索证据或约束顺序；在规则冻结前不把这些失败直接改成战斗数值。GPU 保留为独立实验，不纳入当前正式生成路径。
