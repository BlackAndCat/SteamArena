# 出征 · 难度曲线与节奏方案 v1（给 astra）

> 2026-10-09 · 用户 → Claude（Opus）→ astra。用户：难度曲线不够舒适，第一次出发立刻撞上一辆带甲片的整车，玩家会很不适；**第一、二次出发应该只是捡到一些东西、很快过热、打一两个小兵就够了**。**难度不由 Opus 调**：本文只给参考算法、目标曲线和验收办法，具体数值和数据由 astra 定、跑模拟校准。
> 相关：`docs/expedition-fun.md`（出征玩法 v1、小机械、结算）、`docs/expedition-plan.md`（路线规则）、`tools/route-tuner.html`（出征节奏编辑与真实模拟监控）、`docs/evolve-plan.md`（关卡车进化与胜率筛选）。

---

## 0. 结论先说

1. **跨趟曲线**：难度跟着「第几趟出发」和「这辆车有多强」走，而不是跟着路线上的固定坐标走。前两趟是教学趟：没有一对一决斗，只有小兵，靠过热收尾。
2. **趟内节奏**：学《求生之路》的 AI 导演，用「蓄势 → 高潮 → 喘息」循环来排怪，每段按预算花点数，不按固定坐标堆。
3. **决斗用胜率挑车**：遭遇车按「这一趟的目标胜率」从关卡车里挑，用现有的无画面模拟估计胜率。第一场决斗的目标胜率是 90%。
4. **轻度动态调整**：同一段连续失败两次，下一趟那段的预算降 15%；连续轻松通过，加 10%。玩家看不出来。
5. **验收全靠模拟**：出征节奏编辑器已经能输出逐秒样本，加一个「强度」指标，和目标曲线比对就行。

## 1. 问题

| 现象 | 原因 |
|---|---|
| 第一次出发几秒就撞上一辆整车 | r1 第一场遭遇在 600 px（提速以后约 5 秒），而且是一对一决斗 |
| 新手第一趟就要同时管开车、瞄准、热量、躲炮 | 所有系统一起上，没有分层教学 |
| 死了不知道为什么 | 失败来自决斗里的复杂交火，不是来自一个看得懂的单一原因 |

用户要的前两趟：**捡到一些东西 → 很快过热 → 打一两个小兵 → 回家**。过热是这两趟的「软计时器」：看得见、懂得了，回家装个水罐、散热器，下一趟就能走更远。这正是 Earn to Die、Hill Climb Racing 那种「每趟远一点」的循环，只不过限制资源从油换成了热量。

## 2. 参考的算法和设计方法

| 来源 | 讲什么 | 这里怎么用 |
|---|---|---|
| 心流通道（Csikszentmihalyi《Flow》1990；陈星汉《Flow in Games》2007） | 挑战略高于能力最舒服；太难焦虑，太易无聊 | 用「目标失败率」和「目标胜率」量化挑战，让它跟着玩家的能力涨 |
| 兴趣曲线（Jesse Schell《The Art of Game Design》） | 一段体验要有开场钩子、起伏、高潮、收尾 | 每一趟按「钩子 → 起伏 → 高潮 → 收尾」排（§4） |
| 《求生之路》AI 导演（Michael Booth，AIIDE 2009 主题演讲） | 追踪玩家的「强度」值；按蓄势、保持高峰、高峰消退、放松四个阶段刷怪；强度太高就停刷，让玩家喘口气 | 趟内节奏的核心算法（§4） |
| 《雨中冒险 2》战斗导演（点数制） | 导演按「难度系数 × 时间」攒点数，再按价格买怪 | 每段的怪按预算花点数，不用手摆坐标（§4.3） |
| 动态难度调整（Hunicke《The Case for Dynamic Difficulty Adjustment in Games》2005） | 根据玩家的失败概率悄悄调整供给和压力，玩家不应察觉 | 连续失败或连续轻松时微调预算（§6） |
| 锯齿曲线（关卡设计常用） | 每进一个新区域，难度先回落一截，再爬到更高的峰 | 新路线的开头低于上一条路线的结尾（§3.3） |
| 胜率匹配（Elo 类思路；本项目进化擂台已有胜率筛选，Boss ≥ 50%、奖励车 60/40） | 用对局胜率当难度刻度 | 决斗车按目标胜率挑（§5） |

## 3. 跨趟曲线：第几趟出发 → 这一趟允许出现什么

### 3.1 两个输入

- **n = 出发次数**：存档里已有 `d.route.runs`（结算时 +1）。
- **P = 车的战力分**：建议用现有数据算一个分数，例如「每秒火力 × 0.4 + 总耐久 × 0.3 + 散热能力 × 0.3」，各项按起步车归一化（起步车 P = 1）。具体公式由 astra 定，要求是升级以后分数明显上涨。

### 3.2 这一趟的威胁预算

```
预算 T(n, d) = T0 × 教学系数(n) × 能力系数(P) × 路程系数(d)

教学系数(n)：n = 1 → 0.35，n = 2 → 0.5，n = 3 → 0.7，n ≥ 4 → 1
能力系数(P)：P 的 0.8 次方（车强了怪跟着强，但涨得比车慢，玩家能感觉到自己变强）
路程系数(d)：1 + 0.6 × d / 路线长（越往后越难，终点前大约是开头的 1.6 倍）
```

数字都是起点，由 astra 用模拟校准。

### 3.3 前五趟的目标（用户点名的是第一、二趟）

| 趟 | 允许出现 | 决斗 | 预计怎么结束 | 目标时长 | 目标路程 |
|---|---|---|---|---|---|
| 1 | 物资、煤、2～3 个发条步兵 | 无 | **过热**（约 40～60 秒） | 1 分钟左右 | 路线的 25%～35% |
| 2 | 同上，再加 2 只爬车 | 无 | 过热，或者装了水罐后走得更远 | 1～1.5 分钟 | 比第一趟远 15%～30% |
| 3 | 小兵、爬车、第一辆炮车 | **一场**：没有装甲的弱车，目标胜率 90% | 过热或者打完到中段 | 1.5～2 分钟 | 50% 左右 |
| 4 | 加上炸药桶 | 一场，目标胜率 80% | 自己选择返航，或者到站 | 2～3 分钟 | 60%～100% |
| 5 起 | 全部 | 两场：中段 75%、山顶 60% | 到站 | 3～4 分钟 | 到站 |

- **新路线的锯齿**：第二条路线的第一趟按 n = 3 的预算开局（低于第一条路线结尾的强度），再往上爬。
- **教学趟的过热不罚**：前两趟因为过热结束时，按「拖回院子、东西全带回」算，不按打爆算（现在过热是 `wrecked`，金属会丢一半）。这条要不要做由用户定，放在 §8 的待定项里。

### 3.4 为什么用「趟数 + 战力」而不是固定坐标

固定坐标意味着同一个位置每次都一样难。新手第一趟就会撞上为老手准备的东西，老手第十趟又觉得前半段索然无味。跟着趟数和战力走，就和 Earn to Die 一样：每一趟只比玩家现在的能力高一点。

## 4. 趟内节奏：AI 导演

### 4.1 强度值 I（每秒更新，0～1）

```
I = 衰减(上一刻的 I) + 0.5 × 这一秒掉的耐久 / 车的总耐久 × 20
                     + 0.3 × 600 px 内的敌人数 / 6
                     + 0.2 × 热量（温度 / 120°C）

衰减：每秒乘 0.85（没有新压力时几秒内回落）
```

这些量在 `B.route.samples` 和事件里大多已经有了，只需要补「这一秒掉的耐久」和「附近敌人数」两项。

### 4.2 四个阶段（照 AI 导演）

| 阶段 | 进入条件 | 导演做什么 |
|---|---|---|
| 蓄势 | 默认 | 按预算往前方刷小机械，越刷越密 |
| 保持高峰 | I ≥ 0.7 | 再撑 3～5 秒，不加新怪 |
| 高峰消退 | 保持够了 | 停止刷怪，前方不再出现新威胁 |
| 放松 | I < 0.3 | 6～10 秒只有物资、煤和风景，然后回到蓄势 |

一趟里大约 3～4 个这样的循环，正好对应 §3.3 的 1～4 分钟。决斗本身就是一次高峰，打完以后一定接放松段（残骸、物资、水塔）。

### 4.3 点数制刷怪（照《雨中冒险 2》的导演）

每段攒的点数 = 预算 T(n, d) × 段长 ÷ 路线长。小机械的价格：

| 种类 | 价格（建议起点） | 出现的最早一趟 |
|---|---|---|
| 发条步兵 | 1 | 1 |
| 拾荒爬车 | 2 | 2 |
| 步哨炮车 | 5 | 3 |
| 滚桶炸弹 | 3 | 4 |

导演在蓄势阶段用攒下的点数买怪，摆在镜头外前方 700～900 px，同一组用同一种（例如一排步兵），这样读得出「一组」。

**和现在手摆数据的关系：** r2 现在的 `mobs` 是手摆的。导演可以只决定「这一组刷不刷」，组的位置照数据来。这样改动最小，路线作者依然能控制地形和怪的搭配。

## 5. 决斗车：按目标胜率挑

1. 候选池：关卡车（现有的遭遇已经引用真实关卡车）。
2. 出发前对每辆候选车，用 `SA.Battle.simulate` 跑 N 个种子（进化擂台已有这一套），算出玩家当前这辆车打它的胜率 p。
3. 选 p 最接近这一趟目标胜率的那辆。目标胜率：第一场 90% → 80% → 75%，山顶那场 60%。
4. 第一场决斗的车不能有正面装甲（用户点名：带甲片会让新手不适）。新手的车往往打不穿，打不穿就没有反馈。
5. 结果缓存：按「玩家车的分享码 + 候选车」缓存，车没改就不重算。

**不想做实时模拟时的简化版：** 按 §3.1 的战力分 P 算比值，敌车战力 ÷ 玩家战力 ≈ 0.6（第一场）、0.8、1.0（山顶）。

## 6. 轻度动态调整（玩家看不出来）

- 同一段（按 §4 的循环分段）**连续失败两次** → 下一趟这一段的预算 × 0.85，最低降到 0.6。
- **连续两趟**到达下一段时耐久还高于 70% → 预算 × 1.1，最高 1.3。
- 只调刷怪的数量，不调敌人的伤害和准度（Hunicke 2005：直接改数值容易被玩家察觉，改供给更自然）。
- 只存一个小表 `d.route.dda[路线][段] = 系数`，重置存档就清零。

## 7. 验收：用现有工具量出来

出征节奏编辑器（`tools/route-tuner.html`）和 `SA.Route.simulate` 已经能输出逐秒样本。建议补三件事：

1. **样本里加两项**：这一秒掉的耐久、600 px 内的敌人数。由此算出 §4.1 的强度 I。
2. **目标曲线叠图**：编辑器上把模拟出来的 I(t) 和目标的「蓄势 → 高峰 → 放松」画在一起。
3. **批量验收**（可以用 MCP 的 `steam_arena_simulate` 批量跑）：

| 趟 | 车 | 合格标准（20 个种子） |
|---|---|---|
| 1 | 起步车 | 战斗致死 0 次；过热结束 ≥ 80%；时长 40～80 秒；至少捡到 2 样东西；至少打碎 1 个小兵 |
| 2 | 起步车 + 小水罐 | 战斗致死 ≤ 1 次；平均路程比第 1 趟远 15% 以上 |
| 3 | 换过一两个模块的车 | 第一场决斗胜率 85%～95% |
| 5 | 中期车 | 到站率 50%～70%；每趟至少两次 I ≥ 0.7 的高峰、两次 I < 0.3 的放松 |

**注意：** 现在的无画面模拟由 AI 替玩家开车，没有敌车时 AI 不开火（只往前开）。要验收小机械那几段，AI 得能打小机械。建议加一个最简单的规则：没有敌车时瞄最近的小机械（`SA.RouteMobs.aimPoint` 已经有了，副驾驶就在用它）。
